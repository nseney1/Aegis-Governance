# Privacy Policy

This Privacy Policy explains how **Aegis Guardrails** handles your data, source code, and telemetry. Aegis operates on a strictly local-first, privacy-preserving architecture.

## 1. Aegis MCP Server (`aegis_mcp` — Fully Local & Air-Gapped)

The `aegis_mcp` server provides Model Context Protocol (MCP) tools to LLM-enabled IDEs and agents (e.g., Claude Code, Antigravity, Gemini CLI, Cursor).

**Privacy Guarantees**:
- **Offline & Local**: The `aegis_mcp` server is 100% local. It makes zero outbound network requests to the internet.
- **Local Analysis**: All 17 MCP tools analyze files, git diffs, rule fitness, AST graphs, and security invariants strictly on your local filesystem inside the confined workspace (`confine_path_internal`).
- **Response Projection Denylist (`project_response`)**: Outbound MCP tool payloads pass through `aegis_mcp/projection.py`, which recursively scrubs sensitive raw fields (`task_plan`, `prompt`, `raw_prompt`, and Python introspection attributes) to enforce information partitioning.
- **No Third-Party Telemetry**: No source code, project metadata, or governance reports are ever collected or transmitted to external servers by `aegis_mcp`.

*Note: Your LLM IDE client connecting to the MCP server sends user prompts and returned tool outputs to its configured cloud inference provider (e.g., Google, Anthropic, OpenAI) in accordance with that client's privacy policy.*

## 2. Aegis CLI (`aegis_cli` — Opt-In Cloud Features)

The `aegis_cli` command-line interface runs Layer 1 deterministic verification (`aegis check`), rule management (`aegis rule`), and status reporting (`aegis status`) entirely offline.

**Privacy Guarantees**:
- **Strictly Opt-In Layer 2 Cloud Inference**: External LLM calls (via `DirectSDKBackend`) are only invoked when you explicitly request headless Layer 2 adversarial verification (`aegis check --full`) with an API key configured in your environment. Zero-key alternatives (`aegis check --in-band` via `InBandChargeSheetBackend` or `MCPSamplingBackend`) require no external API keys.
- **Direct Provider Connection**: When `DirectSDKBackend` is used, requests are sent directly to your configured provider using your own environment API keys. Aegis operates no intermediary servers.
- **Zero Background Transmission**: Neither `aegis_cli` nor `aegis_core` ever transmits code or telemetry in the background.

## 3. Data Storage & Local Boundaries (`.aegis/`)

All governance data generated by Aegis Guardrails is stored locally within the `.aegis/` directory of your workspace:
- **Cryptographic Execution Receipts**: Single-use execution receipts managed by `ReceiptManager` (`aegis_core/receipts.py`) use HMAC-SHA256 burn-before-compare verification and expire automatically after 300 seconds; they are never transmitted externally.
- **Telemetry & Rule Manifests**: Local telemetry signals (`.aegis/evidence/signals.jsonl`) and signed rule integrity manifests (`.aegis/rules/manifest.json` generated via `aegis_generate_manifest`) remain strictly local to your workspace.
- **Excluded Secrets & Keys**: Sensitive local files—including HMAC/Ed25519 signing keys (`.aegis/keys/manifest.key`, `.aegis/keys/receipt.key`) and local developer insights (`.aegis/human_insights.jsonl`)—are created with `0600` permissions and excluded from version control via `.gitignore`.
- **User Ownership**: You retain complete ownership and control over all data in `.aegis/`. Deleting the `.aegis/` directory removes all local Aegis state and telemetry records.
